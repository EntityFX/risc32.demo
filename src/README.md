# RISC32.Demo — наглядный учебный процессор

`RISC32.Demo` — маленький, но полный симулятор условной 32-разрядной RISC-машины.
Он предназначен для первого знакомства студентов с машинной командой, регистрами,
флагами, памятью, стеком и вызовами функций. Это не эмулятор x86, ARM или БЭСМ-6.

Проект полностью автономен: собственная solution содержит консольный процессор и
MSTest-тесты и не входит в корневой `Besm6.sln`.

## Быстрый запуск

Из корня репозитория:

```powershell
dotnet run --project RISC32.Demo/RISC32.Demo
dotnet test RISC32.Demo/RISC32.Demo.sln
```

Без аргументов выполняется рекурсивная программа `factorial(5)`. В выводе видны
листинг, вложенность функций, стек и пять логических стадий каждой команды:

```text
FETCH → DECODE → EXECUTE → MEMORY → WRITEBACK
```

В конце `R0` содержит `120`, `SP` возвращается к началу стека, а глубина вызова — к нулю.

Запуск внешней программы:

```powershell
dotnet run --project RISC32.Demo/RISC32.Demo -- RISC32.Demo/examples/programs/02-loop-sum.asm --trace
dotnet run --project RISC32.Demo/RISC32.Demo -- RISC32.Demo/examples/programs/03-memory.asm --dump 0 16
```

Параметры CLI:

| Параметр | Назначение |
|---|---|
| `--trace` | Показать пять стадий каждой команды |
| `--step` | Перед каждой командой ждать Enter и показывать трассу |
| `--max-steps N` | Остановить зациклившуюся программу; по умолчанию 100 000 |
| `--dump START COUNT` | Показать `COUNT` слов памяти с адреса `START` |
| `--help` | Вывести справку без запуска процессора |

Числа CLI и ассемблера можно записывать как `42`, `0x2A` или `0b101010`.

## Устройство машины

- 16 регистров общего назначения `R0`–`R15`, каждый по 32 бита;
- отдельные 32-битные счётчик команд `PC` и указатель стека `SP`;
- флаги `Z` (ноль), `N` (знак), `C` (перенос) и `V` (знаковое переполнение);
- единая память из 65 536 32-битных слов для команд, данных и стека;
- одна команда занимает одно слово, `PC` и адреса указывают номера слов;
- стек начинается сразу за памятью и растёт в сторону меньших адресов.

Команда проходит пять программных стадий. Это учебное разбиение, а не модель
одновременного аппаратного конвейера:

1. `FETCH` читает слово по `PC`.
2. `DECODE` выделяет opcode, регистры и immediate.
3. `EXECUTE` выполняет арифметику или проверяет условие перехода.
4. `MEMORY` читает или записывает память и стек.
5. `WRITEBACK` атомарно фиксирует регистры, флаги, `PC` и `SP`.

Если возникает ошибка, пятая стадия не выполняется: архитектурное состояние
остаётся таким, каким было до команды.

## Форматы 32-битной команды

Старшие восемь бит всегда содержат opcode.

```text
R: [ opcode:8 ][ A:4 ][ B:4 ][ C:4 ][ reserved:12 ]
I: [ opcode:8 ][ A:4 ][ B:4 ][ signed immediate:16 ]
U: [ opcode:8 ][ A:4 ][ signed immediate:20 ]
J: [ opcode:8 ][ signed PC-relative offset:24 ]
S: [ opcode:8 ][ A:4 ][ reserved:20 ]
```

Резервные биты обязаны быть нулевыми. Смещение `J` прибавляется к адресу
следующей команды, поэтому один и тот же машинный код можно перемещать вместе с
окружающим блоком программы.

## Набор команд

| Opcode | Синтаксис | Действие |
|---:|---|---|
| `00` | `NOP` | Ничего не делать |
| `01` | `HALT` | Остановить процессор |
| `10` | `LDI Rd, imm20` | Записать знаковую константу |
| `11` | `MOV Rd, Rs` | Скопировать регистр |
| `12` | `LOAD Rd, [Rb + off16]` | Прочитать слово памяти |
| `13` | `STORE Rs, [Rb + off16]` | Записать слово памяти |
| `14/15` | `PUSH Rs` / `POP Rd` | Положить/извлечь слово из стека |
| `20–24` | `ADD/SUB/MUL/DIV/MOD Rd, Ra, Rb` | Целочисленная арифметика |
| `28–2A` | `AND/OR/XOR Rd, Ra, Rb` | Побитовая логика |
| `2B` | `NOT Rd, Rs` | Побитовое отрицание |
| `2C–2E` | `SHL/SHR/SAR Rd, Rs, Rc` | Левый, логический правый и знаковый правый сдвиг |
| `30` | `CMP Ra, Rb` | Установить флаги как для `Ra - Rb`, не сохраняя результат |
| `40–46` | `JMP/JZ/JNZ/JL/JLE/JG/JGE label` | Безусловный и условные переходы |
| `48` | `CALL label` | Положить следующий `PC` в стек и вызвать функцию |
| `49` | `RET` | Извлечь адрес возврата из стека |

`ADD`, `SUB` и `MUL` оставляют младшие 32 бита результата. `DIV` и `MOD`
считают операнды знаковыми. Деление на ноль диагностируется до изменения
регистров. Количество сдвига берётся из младших пяти бит `Rc`.

### Вызов функции

`CALL` автоматически сохраняет только адрес возврата. Функция и вызывающий код
сами договариваются, какие регистры надо сохранить через `PUSH/POP`. Такое
правило делает смену контекста видимой, а не скрывает её внутри симулятора:

```asm
function:
    PUSH R1
    ; работа с R1
    POP  R1
    RET
```

## Синтаксис ассемблера

Ассемблер нечувствителен к регистру букв, выполняет два прохода и сообщает имя
файла, строку и исходный текст при ошибке.

```asm
; комментарий начинается с точки с запятой
.entry start

start:
    LDI   R1, data
    LOAD  R0, [R1 + 1]
    CALL  function
    HALT

data:
    .word 10
    .word 0xFFFFFFFF
```

- `.entry label` задаёт точку входа;
- `.word value` помещает произвольное 32-битное слово;
- метку можно писать отдельно или перед командой;
- `LDI` принимает знаковое 20-битное число или адрес метки;
- для произвольной 32-битной константы используется `.word` вместе с `LOAD`.

## Проверочные программы

Каталог `examples/programs` содержит десять независимых программ. Все они
ассемблируются и выполняются автоматически в `SampleProgramsTests`.

| Файл | Проверяемые возможности | Итоговый `R0` |
|---|---|---:|
| `01-arithmetic.asm` | `ADD`, `SUB`, `MUL` | `70` |
| `02-loop-sum.asm` | цикл, `CMP`, обратный `JG` | `55` |
| `03-memory.asm` | `LOAD`, `STORE`, метки данных | `66` |
| `04-bitwise-shifts.asm` | `AND`, `XOR`, `OR`, `SHL` | `38` |
| `05-stack.asm` | LIFO и восстановление `SP` | `16` |
| `06-nested-calls.asm` | вложенные `CALL/RET` | `7` |
| `07-signed-division.asm` | знаковые `DIV` и `MOD` | `-9` |
| `08-branches.asm` | `JL/JZ/JG/JGE` и ветвь ошибки | `123` |
| `09-matrix-multiply.asm` | умножение матриц `2×2`, результат в памяти | `19` (`C[0,0]`) |
| `10-cubic-roots.asm` | схема Горнера, перебор и вызов функции | `1` (первый корень) |

Помимо результата тест проверяет `HALT`, восстановление `SP` и нулевую глубину
вызовов. Отдельные модульные тесты покрывают кодирование, флаги, переполнения,
ошибки памяти, стека и деления, лимит шагов, атомарность и консольный интерфейс.

### Математические примеры

`09-matrix-multiply.asm` перемножает две матрицы, записанные построчно:

```text
| 1 2 | × | 5 6 | = | 19 22 |
| 3 4 |   | 7 8 |   | 43 50 |
```

Адреса матриц находятся в `R10`–`R12`, а каждый элемент результата строится из
двух `MUL` и одного `ADD`. Все четыре значения записываются в область `result`.

`10-cubic-roots.asm` находит целые корни уравнения:

```text
x³ − 6x² + 11x − 6 = 0
```

Программа перебирает `x` от `−10` до `10`, вызывает подпрограмму `polynomial`
и вычисляет значение без возведения в степень по схеме Горнера:
`((x − 6) × x + 11) × x − 6`. После `HALT` регистры `R0`, `R1`, `R2`
содержат корни `1`, `2`, `3`.

## Структура кода

Рекомендуемый порядок чтения:

1. `Architecture.cs` — opcode, форматы и кодирование команды.
2. `Assembler32.cs` — два прохода по тексту программы.
3. `Memory32.cs` — проверяемая память слов.
4. `Cpu32.cs` — пять стадий `Step()` и семантика ISA.
5. `TraceFormatter.cs` — учебное представление состояния.
6. `DemoApplication.cs` — аргументы и консольный запуск.

Основной проект использует только стандартную библиотеку .NET. Периферия,
прерывания, кэш, многозадачность и тактовая точность сознательно не моделируются.
