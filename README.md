# RISC32.Demo — наглядный учебный процессор

`RISC32.Demo` — маленький, но полный симулятор условной 32-разрядной RISC-машины.
Он предназначен для первого знакомства студентов с машинной командой, регистрами,
флагами, памятью, стеком и вызовами функций. Это не эмулятор x86, ARM или БЭСМ-6.

Проект полностью автономен: собственная solution содержит консольный процессор и
MSTest-тесты и не входит в корневой `Besm6.sln`.

## Быстрый запуск

Из корня репозитория:

```powershell
dotnet run --project src/RISC32.Demo
dotnet test src/RISC32.Demo.sln
```

Без аргументов выполняется рекурсивная программа `factorial(5)`. В выводе видны
листинг, вложенность функций, стек и пять логических стадий каждой команды:

```text
FETCH → DECODE → EXECUTE → MEMORY → WRITEBACK
```

В конце `R0` содержит `120`, `SP` возвращается к началу стека, а глубина вызова — к нулю.

Запуск внешней программы:

```powershell
dotnet run --project src/RISC32.Demo -- src/examples/programs/02-loop-sum.asm --trace
dotnet run --project src/RISC32.Demo -- src/examples/programs/03-memory.asm --dump 0 16
```

Параметры CLI:

| Параметр | Назначение |
|---|---|
| `--trace` | Показать пять стадий каждой команды |
| `--step` | Перед каждой командой ждать Enter и показывать трассу |
| `--max-steps N` | Остановить зациклившуюся программу; по умолчанию 100 000 |
| `--dump START COUNT` | Показать `COUNT` слов памяти с адреса `START` |
| `--help` | Вывести справку без запуска процессора |

Числа CLI и ассемблера можно записывать как `42`, `0x2A` или `0b101010`.

## Устройство машины

- 16 регистров общего назначения `R0`–`R15`, каждый по 32 бита;
- отдельные 32-битные счётчик команд `PC` и указатель стека `SP`;
- флаги `Z` (ноль), `N` (знак), `C` (перенос) и `V` (знаковое переполнение);
- единая память из 65 536 32-битных слов для команд, данных и стека;
- одна команда занимает одно слово, `PC` и адреса указывают номера слов;
- стек начинается сразу за памятью и растёт в сторону меньших адресов.

Команда проходит пять программных стадий. Это учебное разбиение, а не модель
одновременного аппаратного конвейера:

1. `FETCH` читает слово по `PC`.
2. `DECODE` выделяет opcode, регистры и immediate.
3. `EXECUTE` выполняет арифметику или проверяет условие перехода.
4. `MEMORY` читает или записывает память и стек.
5. `WRITEBACK` атомарно фиксирует регистры, флаги, `PC` и `SP`.

Если возникает ошибка, пятая стадия не выполняется: архитектурное состояние
остаётся таким, каким было до команды.

## Форматы 32-битной команды

### Как читать машинное слово

Биты нумеруются справа налево: младший бит имеет номер `0`, старший — `31`.
Старшие восемь бит `[31:24]` всегда содержат код операции — `opcode`. По нему
декодер понимает назначение остальных полей.

```text
бит:    31                         24 23                         0
        +----------------------------+---------------------------+
слово:  |          opcode            | поля выбранного формата   |
        +----------------------------+---------------------------+
             всегда 8 бит                    ещё 24 бита
```

Одна команда всегда занимает ровно одно 32-битное слово. Поэтому адрес
следующей обычной команды равен `PC + 1`, а не `PC + 4`: память адресуется
словами, а не отдельными байтами.

### Формат `Simple` — команда без операндов

```text
31          24 23                                                   0
+--------------+----------------------------------------------------+
|   opcode:8   |                    нули:24                         |
+--------------+----------------------------------------------------+
```

Используется командами `NOP`, `HALT` и `RET`. Любая единица в младших 24 битах
считается ошибкой кодирования.

### Формат `R` — операции над регистрами

```text
31      24 23  20 19  16 15  12 11                                0
+----------+------+------+------+-----------------------------------+
| opcode:8 | A:4  | B:4  | C:4  |          reserved:12 = 0          |
+----------+------+------+------+-----------------------------------+
```

Обычно `A` — регистр результата, `B` и `C` — исходные регистры:

```text
ADD R3, R1, R2     ; R3 = R1 + R2
```

Код этой команды — `0x20312000`: `0x20` — opcode `ADD`, затем номера
регистров `3`, `1`, `2`, после них двенадцать нулевых бит. У `MOV` и `NOT`
поле `C` равно нулю. У `CMP` поля `A` и `B` обозначают два сравниваемых
регистра, а результат никуда не записывается.

### Формат `I` — память с коротким смещением

```text
31      24 23  20 19  16 15                                        0
+----------+------+------+-------------------------------------------+
| opcode:8 | A:4  | B:4  |          signed immediate:16             |
+----------+------+------+-------------------------------------------+
```

Используется `LOAD` и `STORE`. Эффективный адрес вычисляется в словах:

```text
effectiveAddress = R[B] + signExtend(immediate16)
```

Диапазон смещения — от `−32768` до `32767`. Например,
`LOAD R0, [R1 + 4]` кодируется словом `0x12010004`. Перед обращением процессор
проверяет, что вычисленный адрес попадает в память.

### Формат `U` — загрузка константы

```text
31      24 23  20 19                                                0
+----------+------+--------------------------------------------------+
| opcode:8 | A:4  |             signed immediate:20                  |
+----------+------+--------------------------------------------------+
```

Используется `LDI`. Константа занимает 20 бит и при записи в регистр знаково
расширяется до 32 бит. Допустимы значения от `−524288` до `524287`.
Например, `LDI R2, -1` кодируется как `0x102FFFFF` и записывает в `R2`
значение `0xFFFFFFFF`.

### Формат `J` — относительный переход

```text
31      24 23                                                       0
+----------+---------------------------------------------------------+
| opcode:8 |             signed PC-relative offset:24                |
+----------+---------------------------------------------------------+
```

Используется переходами и `CALL`. Цель вычисляется относительно уже
увеличенного счётчика команд:

```text
target = (PC текущей команды + 1) + signExtend(offset24)
```

Диапазон смещения — от `−8388608` до `8388607` слов. Ассемблер сам вычисляет
его по метке. Например, для перехода с адреса `0x10` на `0x08` смещение равно
`0x08 − 0x11 = −9`, а `JMP` кодируется как `0x40FFFFF7`. Относительная
адресация позволяет переносить блок кода без исправления каждой метки вручную.

### Формат `S` — один регистр и стек

```text
31      24 23  20 19                                                0
+----------+------+--------------------------------------------------+
| opcode:8 | A:4  |                  reserved:20 = 0                  |
+----------+------+--------------------------------------------------+
```

Используется `PUSH` и `POP`. Поле `A` задаёт укладываемый или извлекаемый
регистр. Резервные биты должны быть нулевыми.

### Зачем нужны резервные биты

Резерв оставляет место для будущего развития ISA. Сейчас декодер требует нули
во всех неиспользуемых полях. Это помогает обнаруживать повреждённые команды и
ошибки ручного кодирования вместо молчаливого игнорирования лишних битов.

## Набор команд

В таблицах используются обозначения:

- `Rd` — регистр назначения;
- `Ra`, `Rb`, `Rs` — исходные регистры;
- `imm` — число, записанное прямо в команде;
- `label` — метка исходного текста;
- `mem[address]` — 32-битное слово памяти.

### Управление процессором

| Opcode | Формат | Инструкция | Точное действие | Флаги |
|---:|---|---|---|---|
| `00` | Simple | `NOP` | Перейти к следующей команде, ничего больше не менять | без изменений |
| `01` | Simple | `HALT` | Установить состояние останова после завершения текущего шага | без изменений |

После `HALT` метод `Run` заканчивает работу. Попытка вызвать `Step` ещё раз
считается ошибкой: это позволяет отличить корректный останов от случайного
продолжения исполнения данных как команд.

### Пересылка данных, память и стек

| Opcode | Формат | Инструкция | Точное действие | Флаги |
|---:|---|---|---|---|
| `10` | U | `LDI Rd, imm20` | `Rd = signExtend(imm20)` | обновляет `Z`, `N`; сбрасывает `C`, `V` |
| `11` | R | `MOV Rd, Rs` | `Rd = Rs` | обновляет `Z`, `N`; сбрасывает `C`, `V` |
| `12` | I | `LOAD Rd, [Rb + off16]` | `Rd = mem[Rb + signExtend(off16)]` | обновляет `Z`, `N`; сбрасывает `C`, `V` |
| `13` | I | `STORE Rs, [Rb + off16]` | `mem[Rb + signExtend(off16)] = Rs` | без изменений |
| `14` | S | `PUSH Rs` | `SP = SP - 1`, затем `mem[SP] = Rs` | без изменений |
| `15` | S | `POP Rd` | `Rd = mem[SP]`, затем `SP = SP + 1` | обновляет `Z`, `N`; сбрасывает `C`, `V` |

Пример работы с памятью:

```asm
LDI   R1, numbers      ; R1 получает адрес первого слова
LOAD  R2, [R1 + 2]    ; прочитать третий элемент
STORE R2, [R1 + 3]    ; скопировать его в четвёртый элемент
```

Адреса — номера 32-битных слов. Смещение `+2` означает два слова, то есть восемь
байт в обычном представлении памяти, но умножать его на четыре в программе не нужно.

### Арифметика

| Opcode | Формат | Инструкция | Точное действие | Особые случаи |
|---:|---|---|---|---|
| `20` | R | `ADD Rd, Ra, Rb` | `Rd = (Ra + Rb) mod 2³²` | `C` — перенос из бита 31, `V` — знаковое переполнение |
| `21` | R | `SUB Rd, Ra, Rb` | `Rd = (Ra - Rb) mod 2³²` | `C=1`, если заём не потребовался; `V` — знаковое переполнение |
| `22` | R | `MUL Rd, Ra, Rb` | младшие 32 бита произведения | `C` сообщает о потере старших беззнаковых битов, `V` — о выходе знакового результата за `Int32` |
| `23` | R | `DIV Rd, Ra, Rb` | знаковое целочисленное `Rd = Ra / Rb` | дробная часть отбрасывается к нулю; деление на ноль — ошибка |
| `24` | R | `MOD Rd, Ra, Rb` | знаковый остаток `Rd = Ra % Rb` | знак остатка совпадает со знаком делимого; деление на ноль — ошибка |

Каждый результат — ровно 32 бита. Например:

```asm
LDI R1, -37
LDI R2, 5
DIV R3, R1, R2       ; R3 = -7
MOD R4, R1, R2       ; R4 = -2
```

`0xFFFFFFFF + 1` даёт `0x00000000`, устанавливает `Z=1`, `C=1`. Это не ошибка:
оборачивание результата является определённой частью архитектуры.

### Побитовые операции и сдвиги

| Opcode | Формат | Инструкция | Точное действие | Флаги |
|---:|---|---|---|---|
| `28` | R | `AND Rd, Ra, Rb` | единица остаётся только там, где она была в обоих операндах | `Z`, `N`; `C=V=0` |
| `29` | R | `OR Rd, Ra, Rb` | единица остаётся там, где она была хотя бы в одном операнде | `Z`, `N`; `C=V=0` |
| `2A` | R | `XOR Rd, Ra, Rb` | единица остаётся там, где биты операндов различаются | `Z`, `N`; `C=V=0` |
| `2B` | R | `NOT Rd, Rs` | инвертировать все 32 бита `Rs` | `Z`, `N`; `C=V=0` |
| `2C` | R | `SHL Rd, Rs, Rc` | логический сдвиг влево с заполнением нулями | `C` получает последний вытесненный бит, `V=0` |
| `2D` | R | `SHR Rd, Rs, Rc` | логический сдвиг вправо с заполнением нулями | `C` получает последний вытесненный бит, `V=0` |
| `2E` | R | `SAR Rd, Rs, Rc` | арифметический сдвиг вправо с копированием знакового бита | `C` получает последний вытесненный бит, `V=0` |

Число позиций берётся из младших пяти бит `Rc`, поэтому реально оно всегда от
`0` до `31`. Разница правых сдвигов видна на отрицательном числе:

```asm
LDI R1, -8           ; 0xFFFFFFF8
LDI R2, 1
SHR R3, R1, R2       ; 0x7FFFFFFC — слева пришёл ноль
SAR R4, R1, R2       ; 0xFFFFFFFC — слева сохранилась единица знака
```

### Сравнение и переходы

| Opcode | Формат | Инструкция | Условие или действие |
|---:|---|---|---|
| `30` | R | `CMP Ra, Rb` | вычислить флаги для `Ra - Rb`, не менять регистры |
| `40` | J | `JMP label` | перейти всегда |
| `41` | J | `JZ label` | перейти, если `Z=1`, то есть предыдущий результат равен нулю |
| `42` | J | `JNZ label` | перейти, если `Z=0` |
| `43` | J | `JL label` | знаковое «меньше»: `N != V` |
| `44` | J | `JLE label` | знаковое «меньше или равно»: `Z=1` или `N != V` |
| `45` | J | `JG label` | знаковое «больше»: `Z=0` и `N == V` |
| `46` | J | `JGE label` | знаковое «больше или равно»: `N == V` |

Типичный цикл сначала меняет счётчик, затем сравнивает его и выполняет обратный
переход:

```asm
LDI R1, 10
LDI R2, 1
LDI R3, 0
loop:
    SUB R1, R1, R2
    CMP R1, R3
    JG  loop
```

Переходы `JL/JLE/JG/JGE` выполняют **знаковое** сравнение. Отдельных команд для
беззнакового сравнения в этой небольшой ISA нет.

### Флаги `Z`, `N`, `C`, `V`

| Флаг | Название | Что означает |
|---|---|---|
| `Z` | Zero | 32-битный результат равен нулю |
| `N` | Negative | старший, знаковый бит результата равен единице |
| `C` | Carry | перенос для сложения, отсутствие займа для вычитания или вытесненный бит сдвига |
| `V` | Overflow | математический знаковый результат не помещается в диапазон `−2³¹..2³¹−1` |

`C` и `V` отвечают на разные вопросы. Например, `0x7FFFFFFF + 1` не имеет
беззнакового переноса (`C=0`), но превращает положительное число в
`0x80000000`, поэтому возникает знаковое переполнение (`V=1`). Благодаря `V`
знаковые переходы остаются правильными даже на границе диапазона.

В трассе флаги печатаются в порядке `ZNCV`. Строка `ZNCV=1010` означает
`Z=1`, `N=0`, `C=1`, `V=0`.

### Вызов и возврат из функции

| Opcode | Формат | Инструкция | Точное действие | Флаги |
|---:|---|---|---|---|
| `48` | J | `CALL label` | положить адрес следующей команды в стек и перейти к `label` | без изменений |
| `49` | Simple | `RET` | извлечь адрес возврата из стека и записать его в `PC` | без изменений |

### Как функция сохраняет контекст

`CALL` автоматически сохраняет только адрес возврата. Функция и вызывающий код
сами договариваются, какие регистры надо сохранить через `PUSH/POP`. Такое
правило делает смену контекста видимой, а не скрывает её внутри симулятора:

```asm
function:
    PUSH R1
    ; работа с R1
    POP  R1
    RET
```

Для последовательности `CALL function` стек меняется так:

```text
до CALL:     SP = 65536
CALL:        SP = 65535, mem[65535] = адрес возврата
в функции:   PUSH может сохранить нужные регистры ниже адреса возврата
RET:         PC = mem[65535], SP = 65536
```

Симулятор дополнительно ведёт учебную глубину вызовов. `RET` без парного `CALL`,
извлечение из пустого стека и рост стека до области программы диагностируются
как ошибки. `R0`–`R15` не имеют аппаратно закреплённых ролей: соглашение
«аргумент и результат в `R0`» используется примерами, но не навязывается CPU.

## Синтаксис ассемблера

Ассемблер нечувствителен к регистру букв, выполняет два прохода и сообщает имя
файла, строку и исходный текст при ошибке.

```asm
; комментарий начинается с точки с запятой
.entry start

start:
    LDI   R1, data
    LOAD  R0, [R1 + 1]
    CALL  function
    HALT

data:
    .word 10
    .word 0xFFFFFFFF
```

- `.entry label` задаёт точку входа;
- `.word value` помещает произвольное 32-битное слово;
- метку можно писать отдельно или перед командой;
- `LDI` принимает знаковое 20-битное число или адрес метки;
- для произвольной 32-битной константы используется `.word` вместе с `LOAD`.

## Проверочные программы

Каталог `examples/programs` содержит десять независимых программ. Все они
ассемблируются и выполняются автоматически в `SampleProgramsTests`.

| Файл | Проверяемые возможности | Итоговый `R0` |
|---|---|---:|

| `02-loop-sum.asm` | цикл, `CMP`, обратный `JG` | `55` |
| `03-memory.asm` | `LOAD`, `STORE`, метки данных | `66` |
| `04-bitwise-shifts.asm` | `AND`, `XOR`, `OR`, `SHL` | `38` |
| `05-stack.asm` | LIFO и восстановление `SP` | `16` |
| `06-nested-calls.asm` | вложенные `CALL/RET` | `7` |
| `07-signed-division.asm` | знаковые `DIV` и `MOD` | `-9` |
| `08-branches.asm` | `JL/JZ/JG/JGE` и ветвь ошибки | `123` |
| `09-matrix-multiply.asm` | умножение матриц `2×2`, результат в памяти | `19` (`C[0,0]`) |
| `10-cubic-roots.asm` | схема Горнера, перебор и вызов функции | `1` (первый корень) |

Помимо результата тест проверяет `HALT`, восстановление `SP` и нулевую глубину
вызовов. Отдельные модульные тесты покрывают кодирование, флаги, переполнения,
ошибки памяти, стека и деления, лимит шагов, атомарность и консольный интерфейс.

### Математические примеры

`09-matrix-multiply.asm` перемножает две матрицы, записанные построчно:

```text
| 1 2 | × | 5 6 | = | 19 22 |
| 3 4 |   | 7 8 |   | 43 50 |
```

Адреса матриц находятся в `R10`–`R12`, а каждый элемент результата строится из
двух `MUL` и одного `ADD`. Все четыре значения записываются в область `result`.

`10-cubic-roots.asm` находит целые корни уравнения:

```text
x³ − 6x² + 11x − 6 = 0
```

Программа перебирает `x` от `−10` до `10`, вызывает подпрограмму `polynomial`
и вычисляет значение без возведения в степень по схеме Горнера:
`((x − 6) × x + 11) × x − 6`. После `HALT` регистры `R0`, `R1`, `R2`
содержат корни `1`, `2`, `3`.

## Структура кода

Рекомендуемый порядок чтения:

1. `Architecture.cs` — opcode, форматы и кодирование команды.
2. `Assembler32.cs` — два прохода по тексту программы.
3. `Memory32.cs` — проверяемая память слов.
4. `Cpu32.cs` — пять стадий `Step()` и семантика ISA.
5. `TraceFormatter.cs` — учебное представление состояния.
6. `DemoApplication.cs` — аргументы и консольный запуск.

Основной проект использует только стандартную библиотеку .NET. Периферия,
прерывания, кэш, многозадачность и тактовая точность сознательно не моделируются.
